未登入時點「立即購買」會跳出登入彈窗，不換頁。

## 選票頁（`/order/<eventId>/<sessionId>`）

三種流程的選票頁都在同一路徑，排隊畫面仍為「排隊購票中 請稍候」。

| 項目 | 抽選 | A（入場規定） | C |
| --- | --- | --- | --- |
| 版型 | 票區面板（7 區，均 NT.0、熱賣中） | 票區面板（5 區） | 票種列＋`.count-button` |
| 選位 radio | 只有「電腦選位」 | 「電腦選位」（預設勾選）、「自行選位」 | 無 |
| 清除選擇 | 有 | 有 | 無 |

選位 radio 為 `.v-radio`，零張時有 `v-radio--is-disabled`。
票區面板與票種列是版型差異，與流程類型無關；抽選與 A 都用票區面板。

### 步驟條

步驟條容器 `.stepperPadding`，每步有 `button.stepNum` 與 `.stepText`，狀態 class 為 `currStep`／`afterStep`／`checkedStep`。

| 流程 | 正式步驟文字 |
| --- | --- |
| 抽選 | 選擇票種／輸入資料／確認資料／登記成功 |
| A | 選擇票區／選擇座位／確認資料／付款結帳 |
| C | 選擇票種／填寫資料／付款結帳 |

A 的 order 頁剛載入時，步驟條先顯示 3 步「選擇票種／填寫資料／付款結帳」，載入完成後才換成 4 步。判斷流程類型必須等正式步驟條，不能取第一次讀到的內容。
抽選與 C 只取樣載入後的狀態，未確認是否也有佔位版本。

### A 加張數

展開「一般票(站席)」加 1 張後，標頭剩餘 16→15，加號變 disabled（未確認是否為每單上限），「清除選擇」「下一步」啟用。按下一步後先顯示排隊，約 10 秒內轉到 confirm 頁。

## A 的 confirm 頁（步驟「選擇座位」）

網址 `/confirm/<eventId>/<sessionId>`，與 C 的資料頁同一路徑；頁籤標題為「確認資料」，步驟條則是「選擇票區」checked、「選擇座位」current。
本次為站席電腦選位，畫面沒有座位圖或座位號碼；自行選位與坐席票區未觀察。

頁面頂端出現倒數「請在 m:ss 內完成購票手續並確認訂單」，進頁時約 10 分鐘。內容依序：

1. 「購票明細」：欄位為 票區／票種／數量／單價／金額，下方共 N 張、小計與合計。
2. 「選擇優惠」：radio「無」（預設勾選）與「促銷/優惠折扣碼」，附折扣碼輸入框與停用的「使用」按鈕。
3. h4「聯絡人資訊」：姓名、phone_field、電子郵件三個 text input，由會員資料帶入，**皆為 disabled 且顯示遮罩值**（例如部分字元以 `*` 取代），附鎖頭圖示與「欲修改聯絡人資訊，請前往 會員專區 > 個人資料 修改內容」。
4. 條款 checkbox「我已經閱讀並同意 會員服務條款 與 隱私權政策」、「取消購票」、`button.nextBtn`「下一步」。

未勾條款時下一步 disabled，勾選後啟用。
聯絡欄位由網站帶入會員資料且只能讀到遮罩值。使用者決定 TicketPlus 不比對聯絡人資料，也不需要 `contact.local.json`；聯絡人設定與核對只適用 Klook（見 AGENTS.md）。
與 C 資料頁的差異（購票明細欄位數、選擇優惠區塊、欄位是否鎖定）需要對照 C 的實站紀錄，本次未進入 C 的資料頁。

## 抽選的 confirm 頁（步驟「輸入資料」）

order 頁票區內唯一票種為「登記抽選」NT. 0；加 1 張後加號停用，下一步啟用。
按下一步後顯示「排隊登記中 請稍候」與「若人數眾多可能需要較長等待時間」，文字與購票的「排隊購票中 請稍候」不同；約 10 秒內轉到 `/confirm/<eventId>/<sessionId>`。
頁籤標題為「確認資料」，步驟條「選擇票種」checked、「輸入資料」current。

頁面頂端倒數「請在 m:ss 完成填寫資料並確認登記內容」，進頁時約 10 分鐘。內容依序：

1. 「登記明細」：欄位為 登記票區／登記票種／登記張數／單價／金額，下方共 N 張、登記費用與合計。
2. 「參加者資訊」：每張票一列 `.row.applicant-info`，含編號 `span.applicant-number`、票種文字「登記抽選(01)」、三個空白欄位格，以及 `[role="button"]` 的「編輯」（窄版只顯示 `mdi-pencil` 圖示）。下方提示「※ 請填寫每位參加者之必填欄位。」
3. h4「聯絡人資訊」：與 A 相同，三欄由會員資料帶入、disabled、遮罩顯示。
4. 條款 checkbox、「取消登記」、`button.nextBtn`「下一步」（未填參加者時 disabled）。

參加者資料**不會自動帶入**。按「編輯」開啟 `.v-dialog--persistent` 表單，標題「參加者資訊」，初始只有 `v-autocomplete`「國籍/地區」與停用的「完成」；選擇國籍後應出現證件姓名與證件號碼欄位，但本次未選，未觀察。
以 × 關閉時跳出「關閉表單」確認（您尚未完成資料填寫，關閉後將無法儲存資料），按「確定」後回到原頁，參加者列仍為空。

### 使用者填寫參加者後

同一筆登記單（剩約 5 分鐘時），由使用者自行在編輯表單填寫一位參加者並按完成；工具只讀結構，下列以字元型態描述，不記錄實際值。

- 編號 `span.applicant-number` 的 class 由 `applicant-number grey lighten-1` 變為 `applicant-number`，畫面上數字換成勾選圖示。
- `.row.pl-5` 下四個欄位格：票種文字（`字字字字(99)`）、證件姓名、**一格空白**、證件號碼（`a999999999`，**未遮罩**）。空白格用途未確認，可能是本國籍不需要的欄位。
- 沒有開啟的彈窗；提示文字「※ 請填寫每位參加者之必填欄位。」仍在。
- 下一步在勾條款前仍為 disabled，勾選後啟用。

頁面顯示完整證件號碼，讀取器不可把參加者列的文字送出瀏覽器或寫入紀錄。

### 按下一步之後

在「輸入資料」頁勾條款按下一步，沒有排隊，約 4 秒內直接到 `/checkout/<eventId>/<sessionId>`，頁籤標題「付款結帳」。
與 A 相同，**沒有獨立的「確認資料」頁**：步驟條「選擇票種／輸入資料／確認資料」皆 `checkedStep`，「登記成功」為 `currStep`。倒數持續顯示。

頁面只有「登記明細」：登記票區／登記票種／登記張數／票價／金額，以及共 N 張、登記費用、折扣、系統服務費、合計與底部總金額。沒有參加者、聯絡人、取票或付款方式區塊。
`.row.py-2.py-md-3.no-gutters` 摘要列 1 列。底部為「上一步」與 `button.nextBtn`「確認登記」；本次未按，登記未送出，留待逾時。

按下一步後約 10 秒內轉到 `/confirmSeat/…`（取樣時未看到排隊畫面，可能過短未取到），頁籤標題只有「確認座位 | Ticket Plus遠大售票系統」，不含活動名稱。
步驟條「選擇票區」checked、「選擇座位」current；頂端倒數「請在 m:ss 內完成購票手續並確認訂單」，約 10 分鐘。

內容只有一個區塊「確認選位結果」（`.bg-tranparent-yellow`），表頭 票區／位置／票種／金額，每個座位一列 `.row.py-2.py-md-3.no-gutters`，例如 C 區／`25 排 7 號`／預售票／NT. 5,800。

按下一步後約 5 秒內到 `/confirm/…`，頁籤標題「確認資料 | <活動名稱> | …」，步驟條前兩步 checked、「確認資料」current（站席版本同一路徑卻是「選擇座位」current）。

現有程式碼的路徑規則只接受 order／confirm／checkout，提交後遇到 confirmSeat 會成為 unsupported-url，結果為已提交但未確認（unknown）。

## A 的 checkout 頁

在 confirm 頁按下一步後直接到 `/checkout/<eventId>/<sessionId>`，**沒有獨立的「確認資料」頁**。步驟條前三步同時為 `checkedStep`，「付款結帳」為 `currStep`。

頁面區塊為「取票方式」「付款方式」「購票明細」；付款方式 radio 有信用卡線上刷卡、ATM 虛擬帳號與超商取票付款相關選項，皆未預設勾選。底部有總金額、「上一步」與 `button.nextBtn`「前往付款」。
`.row.py-2.py-md-3.no-gutters` 摘要列 1 列。倒數持續顯示。

## 結論與未驗證

- 一般購票有兩種步驟條（C：選擇票種／填寫資料／付款結帳；A：選擇票區／選擇座位／確認資料／付款結帳），實際經過的頁面有三種：

  | 情況 | 頁面順序 | confirm 頁的 current 步驟 |
  | --- | --- | --- |
  | C（票種列） | order → confirm → checkout | 填寫資料 |
  | A 站席（TOP女神一般票） | order → confirm → checkout | 選擇座位 |
  | A 坐席（LOOKMHEE C 區，電腦選位） | order → confirmSeat → confirm → checkout | 確認資料 |

  A 的步驟條寫著「選擇座位」，不代表一定出現 confirmSeat；是否有選位頁只能看提交後實際到達的網址與內容。
- A 的 order 頁「先 3 步再 4 步」是同一頁載入中的暫時畫面，文字剛好與 C 的正式步驟條相同，不是另一種流程。
- 抽選的 order 頁與 A 共用票區面板版型，差異在場次按鈕文字、步驟條與終點「登記成功」。
- 抽選的「輸入資料」也在 confirm 路徑，但每位參加者必須經編輯表單填寫國籍與證件資料，網站不自動帶入。
- 抽選與 A 一樣在 confirm 按下一步後直接到 checkout；「確認資料」只是步驟條上的已完成步驟，實際停止點是 checkout 頁的「確認登記」之前。
- 未觀察：抽選參加者表單選國籍後的欄位、外國籍參加者列、多張登記、按「確認登記」後的結果；A 的自行選位、多張坐席的 confirmSeat 列、confirmSeat 是否出現失敗彈窗；C 的 confirm 頁在本帳號下是否同樣鎖定欄位；入場規定以外的活動頁彈窗。

## 使用者決定（2026-10-17）

- 聯絡人：TicketPlus 由網站帶入會員資料，不比對 `contact.local.json`（已寫入 AGENTS.md）。
- 流程類型 UI：活動編輯頁「活動網址」下方，以 fieldset 標題「購票流程」放兩個單選項「購票」「登記抽選」，外觀比照 Klook「功能啟用」；不細分 A／C，由實際頁面決定是否經過 confirmSeat。
- 頁面判斷：網址決定頁面種類，同一次 DOM 快照的內容確認已完整載入且沒有混雜；`/confirm` 以有無「參加者資訊」、`/checkout` 以「前往付款」或「確認登記」分辨購票與抽選，再依流程類型決定動作。
- 不讀步驟條：A 的 order 頁步驟條有載入中暫時內容，A 站席寫「選擇座位」卻沒有選位頁，不可靠。流程類型設錯由活動頁場次按鈕文字（立即購買／立即登記）在點擊前擋下。步驟條觀察僅作參考。
- 購票停止點：資料頁確認聯絡欄位有值（不比對內容）後勾條款、按一次下一步，核對抵達同場次 `/checkout`（「付款結帳」為 current、唯一「前往付款」）後停止；付款方式與「前往付款」由使用者操作。按下一步後未能確認抵達即回報 unknown，不重試。此決定取代先前「不勾條款、不點資料頁下一步」的規則。
- 抽選停止點：停在第三步「確認資料」，不送出登記。實站上這是 `/checkout` 頁、步驟條 current 為「登記成功」、按鈕「確認登記」之前。
- 抽選參加者：工具不讀取、不保存、不填寫證件資料。到「輸入資料」頁後回報等待，由使用者在瀏覽器填完所有參加者，再於 GUI 按「參加者已填完」。
- 確認後工具只核對一次：同活動同場次的 confirm 頁、步驟條為「輸入資料」、沒有開啟的編輯表單或關閉確認、參加者列數等於設定張數且每列都標示為已填（依編號徽章與欄位有無值判斷，不讀內容；空白格規則待確認）。任一不符即停止並說明原因；通過後勾條款、按一次下一步，核對抵達同場次 checkout 頁（前三步 checked、「確認登記」存在）後停止，不按「確認登記」。
