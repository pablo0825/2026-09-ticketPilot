# 系統架構與資料流

本文件用架構圖介紹系統組成，再用時序圖說明各部分之間的資料流。

## 整體架構

```mermaid
flowchart TB
    GUI["GUI<br/>設定要買的票、查看購票進度"]
    Server["後端服務<br/>檢查能否開始、安排購票工作"]
    Worker["購票子程序<br/>開啟瀏覽器、選票並檢查結果"]
    Files[("本機資料<br/>購票設定、執行紀錄、占用鎖")]
    Site["TicketPlus 網站"]

    GUI <-->|"送出操作要求、接收進度"| Server
    Server <-->|"交代購票工作、接收回報"| Worker
    Server <-->|"讀取設定、保存紀錄與管理占用"| Files
    Worker -->|"核對占用，結束後解除"| Files
    Worker <-->|"透過瀏覽器選票與送出資料"| Site
```

箭頭表示互動關係，不代表執行順序。除了 TicketPlus 網站，其餘部分都在你的電腦上。

「占用鎖」用來防止同時啟動多個購票流程。子程序必須等流程與瀏覽器都結束，才解除占用。

## 時序圖的溝通方式

| 標示 | 意思 |
| --- | --- |
| HTTP API | GUI 提出要求，後端回覆處理結果 |
| SSE | 後端透過 HTTP 長連線，持續把完整的最新狀態送給 GUI |
| IPC | 後端與購票子程序互傳訊息 |
| 檔案讀寫 | 從硬碟讀取資料，或將資料保存到硬碟 |

## 使用的技術

| 技術 | 用在哪裡 | 用途 |
| --- | --- | --- |
| React | GUI | 建立設定與進度畫面 |
| Node.js | 後端服務、購票子程序 | 執行服務與購票程式 |
| Playwright | 購票子程序 | 操作瀏覽器、讀取網站狀態 |
| Node.js `fork` | 後端服務 | 建立購票子程序及 IPC 通道 |
