# 人工驗證逾期恢復

`FLOW_PAUSE` 是可選的人工測試入口，每次執行最多暫停一次。
未設定或空字串時不暫停；其他不支援的值會在開啟瀏覽器前報錯。
必須在可互動的終端機執行，不接受管線自動輸入。

## 選位過期

```bash
FLOW_PAUSE=seats WEBDRIVER_EXPERIMENT=1 npm start
```

配位核對完成後、按座位確認前暫停。等網站顯示「未於時限內確認，票券預留失敗」，
不要手動按 OK；回終端機直接按 Enter。程式重新檢查選位狀態，符合恢復條件才按 OK、
等待選票區返回並重新取得座位。第二輪不再暫停。

## 個人資料過期

```bash
FLOW_PAUSE=contact WEBDRIVER_EXPERIMENT=1 npm start
```

需先設定 `contact.local.json`。程式填寫、核對個資後暫停，仍在準備流程的恢復範圍內。
等過期彈窗出現，不要手動按彈窗確認；回終端機按 Enter。
程式重新核對頁面，辨識明確過期後處理彈窗，重新選票、配位及填寫資料。

## 判讀結果

- 預期依序看到測試暫停、繼續、`RECOVERING`、`EVENT_PAGE`，再走正常流程。
- 正常完成會到 `PAYMENT_READY`，停在實際付款前。恢復後會繼續提交個資；測試可能建立待付款訂單。
- 未過期就按 Enter，會直接繼續正常流程，不會強制模擬過期或消耗恢復額度。
- 三種逾期仍共用一次恢復額度，若先前已恢復過，再次過期會停止。
- Ctrl+C 或終端輸入關閉會取消流程，即使頁面已過期也不會重跑。
- 已嘗試座位確認或個資提交而結果不明時仍停止，不重送。
- 沒有個資設定時可使用 seats 暫停點，正常終點仍是個資頁；contact 暫停點會在啟動前拒絕缺少設定。

測試後人工確認是否重新取得座位、核對條件及抵達預期終點。
本機測試已涵蓋暫停、恢復銜接與取消；實站結果需另外記錄。

## 返回途中又遇到排隊逾期

選位或個資預留過期後，返回原活動頁的等待期間，若出現已知的
「抱歉，時間到了！請返回並重新排隊」彈窗，會接續按一次 OK，等待選票入口恢復。
日誌會顯示「本次恢復途中出現排隊逾期」，不代表開始第二次購票重跑。

- 整次執行仍只有一次購票恢復額度。
- 返回途中額外處理排隊彈窗最多一次；原始恢復就是排隊時，不開放額外排隊處理。
- 原彈窗與接續排隊彈窗各只嘗試點擊一次；多個可見 alert 同時存在時停止，不任選按鈕。
- 選票入口一旦核對完成，就結束這次返回等待；之後再出現逾期屬新的例外，受原上限限制。
- 原彈窗點擊最多等待 30 秒，返回階段最多等待 30 秒；接續排隊點擊與其返回等待也各最多 30 秒。
  各階段只有一次，不因狀態變化反覆重設期限。未知彈窗或無法恢復時停止，不自動重整。
- 票券區持續空白仍不會自動按「重新整理」。

本機 fixture 已驗證選位／個資返回、延遲排隊彈窗、延遲選項、重複／未知／多個彈窗及錯誤活動頁。
使用者這次實站回報的第二個彈窗尚未重新擷取 DOM，僅沿用先前已觀察的排隊彈窗格式；
實站若不符合這個精確格式，會停止，需另外觀察。
