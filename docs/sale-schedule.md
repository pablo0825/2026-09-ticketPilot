# 開賣時間設定

在 `src/config/event.config.ts` 的 eventConfig 加入可選設定：

```ts
saleSchedule: {
    saleAt: "2026-10-10T10:00:00+08:00",
    advanceSeconds: 1,
},
```

上例僅供格式示範，不代表任何活動的實際開賣時間。必須填完整、有效的台灣日期時間與 `+08:00`。提前量限 1 或 2 秒，預設 1 秒。沒有設定時，沿用既有立即購票流程；設定錯誤則在啟動瀏覽器前拒絕。

## 流程與界線

1. 確認登入，未登入等待手動登入；到目標活動頁驗證身分、提示及選票區。
2. 開賣前可接受唯一可見票券區內明確的「即將開賣」，或已有票券選項；顯示待命，不選票。
3. 提前 1 秒刷新一次，等待新頁 `domcontentloaded` 和 DOM。導航與 DOM 共用最多 60 秒，不在載入中再刷，導航失敗直接停止，不讀舊頁面作決策。
4. 新頁有票券選項，最早到正式開賣才交給原順位策略。選項停用仍交原策略判斷；不能把停用或空白當成即將開賣。
5. 新頁明確「即將開賣」，且已到開賣時間、距上次刷新起始至少 3 秒，才再次刷新。09:59:59 刷新後仍未開賣，下一次最早 10:00:02。慢回應已超過 3 秒時，可在狀態確認後再刷。
6. 每次等待受固定 `saleAt + 120 秒` 截止限制。登入等待最多五分鐘，但排程模式同時受此截止限制。截止後才啟動直接停止；開賣後、截止前啟動會立即刷新。
7. 已知排隊逾期優先於刷新：保留彈窗，到正式開賣交給原恢復流程。排程不按 OK、不建立額外額度。恢復仍維持原本 30 秒與入口完成條件，失敗停止。
8. 一旦交给購票／恢復流程，排程永久退出，沒有背景 timer。兩分鐘截止不再干擾座位確認或提交；原策略實例及恢復額度不重建。

未知提示、錯活動頁、殘留選位、HTTP 失敗或載入逾時均停止。不增加自動重送或付款行為。

## DOM 證據與驗證限制

先前 BABYMONSTER 活動頁觀察：唯一 `#ticket-options` 內有 `.package-wrapper.stateText`，可見文字為「即將開賣」，沒有 `.spec-LwNjSh` 選項。判斷限定該結構與完整文字；空白本身不是預售證據。與選項同時出現或多個狀態容器視為矛盾。

本機測試以此結構模擬預售、延遲載入與開放，未驗證真實開賣瞬間。提前刷新依本機系統時鐘，電腦休眠或時鐘不準會影響實際觸發時間，並不保證搶票成功。
