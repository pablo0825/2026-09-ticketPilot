# 順位策略與 Klook 失敗返回

## 已實作與限制

每個 `eventConfig.targets` 項目包含日期、時間、票區、張數、連位要求與
`expectation`（活動名稱、單價、總價）。啟動時驗證所有目標。
目前保留既有 A 區一張設定；沒有擅自新增 B 區或變更購買張數。

`PriorityStrategy` 在整次執行建立一次。明確失敗且安全返回後才推進；
成功結果包含實際目標、價格與新座位，供確認、摘要及付款核對使用。
排隊／預留過期恢復重試當前順位，不退回第一順位，也不重設額度。
順位切換不是過期恢復，不消耗其額度；返回失敗則終止，不轉用其他恢復。
所有順位均明確失敗時回報 `NO_TARGET_AVAILABLE`，不循環、不買清單外票種。

## Klook 失敗彈窗接線

已依使用者要求啟用 Klook adapter 的失敗返回，沿用已觀察的 `.klk-modal-alert`
容器。只接受完整可見文案「已經沒有票了」或「選位失敗，請重試」
（允許空白、逗號及末尾句號／驚嘆號差異），且只有一個可見提示及
一個可操作的 OK／確認／確定按鈕。不是所有相同 CSS 的彈窗都會被按下。

只在本次「下一步」送出後辨識；選票前已存在的無票提示不處理。
辨識後、點擊前再次核對，已配出座位卻同時顯示失敗視為矛盾而停止。
每次失敗只嘗試關閉一次；等原活動選票入口恢復、提示及座位外殼消失後，
才進下一順位。不額外 reload，返程遇排隊過期也不接續恢復。
返回完成後、下一目標開始前若遇已知排隊過期，仍可走既有獨立排隊額度。

**接線已啟用，但新無票彈窗的結構與返回行為尚未在實站重現驗證。**
本機測試沿用既有 Klook 結構，不能據此保證新彈窗實際使用同一結構；
若不符合完整辨識條件，程式停止並進入診斷，不嘗試猜測按鈕。
目前設定仍只有 A 區一張；要換 B 必須由使用者在 targets 加入 B 的完整條件及價格。

選票「下一步」只送一次，之後觀察座位、提示及等待上限。
未支援提示、資料不符或等待超時停止，不換區、不重送。
已知排隊／預留過期仍由原恢復模組核對。
座位確認與個資提交不重送；連位仍僅核對網站勾選，未獨立驗證座位相鄰。

## 異常證據

選票／配位階段停止後，在 `diagnostics/<隨機ID>/failure.json` 保存原活動頁
可採集容器的白名單結構、已知提示及按鈕名稱。不保存任意文案、屬性、
輸入值、整頁 HTML、cookie、storage、URL query 或表單；目錄已加入 gitignore。

互動終端中可手動處理彈窗後按 Enter，再保存 `returned.json`。
這個 Enter **只採集、不恢復購買**；Ctrl+C 結束，非互動環境只採一次。
離開原活動頁或寫檔失敗只回報限制，不重啟流程。

未知 DOM 無法保證取得完整彈窗。為避免未知區塊截圖夾帶個資，這一階段
不自動截圖；需要使用者另外保留彈窗局部截圖及完整文案。紀錄不包含
完整 selector，後續仍需人工檢查實際 DOM、唯一按鈕與返回前後狀態。

## 驗收

本機測試涵蓋 A 失敗到 B、全部失敗、延遲返回、返回失敗、B 過期仍試 B、
實際成功價格傳遞、未支援彈窗零點擊、診斷白名單及 Enter 只採集。
既有過期額度、確認與提交邊界測試應保持通過。
