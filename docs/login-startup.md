# 啟動登入確認

2026-10-03 使用者在側邊瀏覽器手動展示登入與登出；另唯讀確認首頁結構。

- 已登入：`nav.default-header` 內唯一可見 `.default-header_logged-in`，內有唯一可見 `.default-header_avatar`。
- 未登入：同頁首唯一可見 `.default-header_signin`，没有可見已登入容器。
- 登入頁面板為 `.klk-login__dialog`。面板消失不能單独當成登入成功。
- 登入頁 `.klk-login-last-logged-*` 是上次登入紀錄，不能當成目前已登入。
- 活動頁外層是 header，首頁外層是 div；兩者共用 nav.default-header，因此不以 header 元素限定。
- 本次手動登入後由 signin 導往 bookings；程式不要求固定返回 bookings。

程式只取可見結構，不讀帳戶名稱、頭像網址、帳密、驗證碼、cookie 或 storage。
非 Klook HTTPS 頁面回報 unknown，不讀其登入 DOM；使用者第三方登入可在期限內自行完成。
這是網站 UI 的登入狀態判斷，不是對伺服器 Session 永久有效的保證。

## 啟動行為

載入原 browser-profile → 導覽 Klook 首頁 → LOGIN_CHECK → 未登入則 WAITING_FOR_LOGIN。
未知狀態最多等待30秒；第一次明確未登入時開始5分鐘人工登入期限，重複未登入不延長。
每500ms觀察一次，不重新整理，不代填、不代按登入，也不讀使用者輸入值。
導頁時DOM暫時不可讀仍在原期限內等待；關閉瀏覽器或期限用盡停止。

登入成功後只導覽一次設定活動頁，核對HTTP、目標網址、登入標記及可見選票選項。
READY表示可以交给既有策略，不表示有票、日期/價格已驗證或已預訂。
停用選項不阻擋準備完成；各目標仍由原選票流程完整核對。
空白選票區逾時時回報可能未開賣或載入異常，不從缺少選項猜測售罄或未開賣。

活動頁重新要求登入、錯誤/封鎖頁、未知彈窗或已有選位畫面會停止，不進行自動購票。
唯一已知排隊過期彈窗例外：不宣告READY、不點OK，交給原prepareBooking恢復流程，
仍消耗原先單次queue額度。登入準備本身不持有、不重設購票恢復額度。
選位確認、個資提交、付款前停止與原順位策略不變。

本機fixtures驗證啟動與失敗邊界；側邊瀏覽器的DOM觀察不等於已用修改後npm start完成實站驗證。
