# Klook 配位結果格式

## 已觀察的兩種格式（2026-10-03）

- Jason Mraz：兩張票有兩個 `.list_item-jYRAN7`，每列依序為「區／排／座位」及各自的 `ins` 值，例如 A2／7／24、A2／7／22。
- 斑恩：兩張票只有一列「區／一般 票」，但 `.seat_list_top-Bk0UC9` 是已選 2 個座位、`.con_seats-a3N26U` 是共計 2 個座位，單價 1,280、總額 2,560。預訂摘要也只有一筆「一般 票」，張數標籤為「門票」，值為 2。
- 劃位格式的 `.seat_list_top-Bk0UC9` 同時包含張數及「自行選位」按鈕；張數限定讀取其唯一 `:scope > div > div` 子欄位。
- 動態取樣曾在兩場觀察到張數、明細、總額及可按確認按鈕先出現，票種名稱和載入完成訊號稍後才出現。不能只以按鈕啟用判定完成。
- `.seatsio-loading-screen` 位於 `.seatModal_main-Dpti0D` 內、右側面板之外。退出時加入 `hide`，仍可能是 `display:flex` 且有尺寸，但 opacity 為 0。

這些是已知資料呈現格式，不代表程式能推斷所有活動的實際座位規劃。不用政策文案、圖片或使用者輸入的座位模式來選擇驗證方式。

## 實作邊界

`seatSelector.ts` 同一次 DOM 快照讀取唯一清單、票種、已選張數、共計張數、總額和完整帶標籤的明細。已知座位圖 loader 或 aria-busy 尚在顯示時繼續受控等待。明細、標籤、值及祖先的隱藏狀態也會檢查，避免從隱藏 DOM 取得舊資料。

- `reserved`：每列必須有完整區／排／座位，列數等於購票張數，座位不得重複。
- `general`：目前只接受單列「區／一般票」；以已選、共計及金額核對張數。不把任意缺少座號的結果當成一般票。
- 未知、混合、重複、缺漏或矛盾資料不通過；不標示售罄、不因此換順位。
- 多張一般票若要求連位，停止並說明無法驗證。劃位票沒有新增按座號差計算連位的規則。
- 確認前重讀，類型及配位內容必須與先前驗證結果一致。確認不自動重試。
- `bookingSummary.ts` 依同一份 Allocation 核對逐座資料或單一一般票群組，並照常核對活動、場次、票種、單價、張數與總額。
- Strategy 和恢復額度不變；恢復後重新取得結果，不沿用過期配位。

本次程式以本機 fixture 驗證，尚未用修改後程式完成實站選位確認。新的網站格式仍需獨立觀察後支援。
