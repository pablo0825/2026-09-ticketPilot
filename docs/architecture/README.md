# 系統架構與資料流

GUI 把購票要求交給後端服務，後端檢查後啟動購票子程序。子程序操作 TicketPlus 網站，再透過後端把進度和結果傳回 GUI。

這三個部分都在你的電腦上執行；活動設定與執行紀錄也保存在本機。

## 四個欄位代表什麼

| 欄位 | 負責什麼 |
| --- | --- |
| GUI | 讓你設定活動、開始購票和查看進度的畫面 |
| 後端服務 | 接收 GUI 的要求，檢查能不能執行，再安排購票工作 |
| 資料檔案 | 保存活動設定、執行紀錄與占用鎖的硬碟檔案；它不是程序 |
| 購票子程序 | 實際操作購票網站，並把進度和結果回報給後端 |

「占用鎖」是一個檔案，用來防止多個購票流程同時執行。圖中省略使用者和購票瀏覽器，集中呈現這四個部分的互動。

## 箭頭怎麼讀

| 標示 | 意思 |
| --- | --- |
| HTTP API | GUI 提出要求，後端回覆處理結果 |
| SSE | 後端持續把最新狀態送給 GUI |
| IPC | 後端與購票子程序互傳訊息 |
| 檔案讀寫 | 從硬碟讀取資料，或將資料保存到硬碟 |

從上往下看每個流程，箭頭指向接收資料或指令的一方。指回自己的箭頭，表示該部分正在做內部處理。

黃色區塊表示進度回報會重複發生。不同連線的訊息可能交錯到達，例如 GUI 不一定先收到 HTTP 回應，再收到 SSE 更新。

## 先分清楚「有結果」和「已結束」

- **有結果**：自動操作已停在交接位置，或已停止、失敗、結果不明。這不代表已付款或完成最終抽選登記。
- **已解除占用**：正常情況下，流程和瀏覽器都結束，子程序核對後刪除鎖檔。後端還要確認子程序已結束，才允許開始下一輪。

## 技術補充

GUI 使用 React；後端服務和購票子程序使用 Node.js。購票子程序透過 Playwright 操作瀏覽器。

- **SSE** 使用 HTTP 長連線，每次傳送完整的最新狀態。
- **fork** 是後端建立另一個 Node.js 程序的動作，不是通訊協定。
- **占用憑證 `lease`** 包含鎖檔路徑和 token，透過 IPC 傳給子程序。token 是核對用的識別值，讓子程序確認自己持有這次占用。

本文件依程式碼整理，不代表已驗證真實售票網站。模組分工與擴充規則另見 [新增平台指南](../adding-platform.md)。
