TicketPilot 的 GUI、後端服務與購票子程序都在你的電腦上執行。購票子程序透過 Playwright 操作外部的 TicketPlus 網站。

## 四個欄位代表什麼

| 欄位 | 責任 |
| --- | --- |
| GUI | 顯示活動設定、進度和操作按鈕的 React 前端 |
| 後端服務 | 接收 GUI 請求，管理子程序、執行紀錄及目前狀態 |
| 資料檔案 | 硬碟上的活動設定、執行紀錄與購票占用鎖；它不是程序 |
| 購票子程序 | 獨立的 Node.js 程序，負責操作購票瀏覽器及核對網站結果 |

圖中省略使用者與購票瀏覽器，以便集中閱讀模組之間的資料流。

## 箭頭上的溝通方式

| 標示 | 意思 |
| --- | --- |
| HTTP API | GUI 提出要求，後端回覆結果 |
| SSE | 使用 HTTP 長連線，由後端持續向 GUI 傳送完整的最新狀態 |
| IPC | 後端與購票子程序互傳訊息，不經過 GUI |
| 檔案讀寫 | 從硬碟讀取資料，或將資料保存到硬碟 |
| Node.js fork | 後端建立另一個 Node.js 程序；這是啟動動作，不是通訊協定 |

箭頭表示動作或訊息的方向。跨 HTTP、SSE 與 IPC 的訊息非同步傳遞，不應把圖中上下位置解讀為不同連線的實際送達順序。各節會說明需要注意的並行行為。

## 兩種容易混淆的狀態

- **執行有結果**：自動操作已停在交接位置，或已停止、失敗、結果不明。不代表付款或最終抽選登記完成。
- **購票占用已解除**：正常情況下，流程和瀏覽器都結束，子程序核對占用憑證後刪除鎖檔。只有結果回報，還不能保證可以開始下一輪。

占用憑證 `lease` 包含鎖檔路徑和 token，透過 IPC 傳給子程序。子程序用它核對自己是否持有這次占用。
