# 啟用排隊流程

在 GUI「活動與順位」勾選「啟用排隊流程」，隨活動儲存。
預設關閉，舊活動缺少此欄位也視為關閉。CLI 可設定 `queueEnabled: true`。
關閉與缺值正規化為省略，不改變舊活動的設定指紋。
啟用但直接到選票頁的活動仍走原流程；未啟用卻到排隊頁則停止。

## 正常排隊

只在啟動／開賣刷新階段接手同來源、同語系的 queue 頁。
核對 `iframe.dynamic-frame` 的 CDN 快照活動編號，不能把 queue 編號當活動編號。
不改設定活動網址，不直接以 queue 網址啟動，不修改任何使用者的活動設定。

1. 等「開賣倒數」歸零，嘗試點「排隊購票」一次。
2. 等待排隊，百分比滿格不是購票頁就緒的證據。
3. 允許網站在 100% 後自行重載同一頁；保留點擊紀錄與原截止時間。
4. 看到「輪到你了，請盡快完成購票！」及有效順位保留倒數，嘗試點「繼續預訂」一次。
5. 回到原活動頁後重新核對登入、提示、選票區及最早開賣時間，再接原選票流程。

控制項先依 button role 與精確名稱搜尋；零匹配才用精確文字備援。
文字須位於唯一 `.event_queue_desktop` 排隊區，且本身或最近控制項具按鈕、連結、
onclick 等明確結構（僅有 tabindex 不算）；停用父層、多個匹配或只有普通文字都不點。
不得強制點擊；點擊前即記錄嘗試，點擊結果不明不改另一種定位方式重按。

總等待上限固定一小時，未知／重載畫面最多等待一般載入期限（預設 30 秒）。
順位保留倒數另有獨立截止，不因刷新或數字增加而延長。
程序不主動 reload、不點離開、不因保留過期重新排隊。
已開始排隊可以超過開賣後兩分鐘；全新啟動的過晚排程仍依原規則拒絕。

## 與既有流程的界線

正常排隊不消耗或重設 queue／reservation 恢復額度。
不更改共用 `isEventPageReady`、選票、選位確認、聯絡資料提交或付款停止界線。
預留／排隊逾期恢復途中若到真正排隊頁，仍依原規則停止，本次不擴張恢復範圍。
放行後若再次回到排隊頁停止，不重新建立一次等待或點擊預算。

## 實站依據與限制

2026-10-13 已觀察英文隊列：`.event_queue_desktop`、`.queue-banner`、
`.queue-title`（You're now in the queue!）、`.qmotion__pct`（1%）、`.queue-leave`。
活動 iframe src 為 `https://cdn.klook.com/event/queue-snapshot/<活動ID>/<語系>/web/<檔案>.html`。

中文倒數、排隊購票、輪到你了、順位保留倒數及繼續預訂文字來自使用者截圖；
100% 後網站自動刷新由使用者回報。兩按鈕 HTML、完整實站刷新與返回尚未親自驗證。
操作辨識目前以中文文案為準；英文已在隊列的等待標題可辨識，但不猜測英文入隊／繼續按鈕。
實際結構或文案不符合時會停止，不判定售罄。
本機 fixture 驗證邏輯，不代表已完成實站端到端購票驗證。
