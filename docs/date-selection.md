# 日期選擇與完整場次核對

2026-10-03 觀察斑恩與 Jason Mraz 的 `#ticket-options`：兩者日期群組皆為
`.skuGroup-hk2pfU`、標題 `.name-Cu4gxk`，選項 `.spec-LwNjSh`，文字分別是
`11月15日(週日)`、`11月2日(週一)`。選項 DOM 沒有提供完整年份。

選票階段改以唯一日期群組內的可見選項核對，不再讀取 `#ticket-info` 活動介紹。
中文月日允許缺少年份；完整年月日則必須連年份一起符合設定。星期不作為推算年份的依據。
無年份且有歧義的數字日期（如 `11/02`）、區間、未知格式均不猜測。

先要求唯一匹配，再確認可操作；已選但停用仍停止。初次選日期／時間時，
唯一可見匹配項同時具有 `disabled-ImixBj` 與 `soldout-sBHQQa` 且未選中，
可回報送出前不可選，由既有 STRICT 順位前進；不點該選項、不返回、不扣恢復額度。
缺失、歧義、僅 disabled 或僅 soldout 等未知／矛盾狀態仍停止。
後續選票操作後重新定位、解析並核對選取狀態，日期或時間變停用仍停止，不能變成跳順位。

無年份選項只能證實月日。完整年份延後在配位面板唯一可見的
`.pc_header_center-mSlDdM > span` 核對，按確認前再次核對，預訂摘要再核對一次。
因此錯年份可能在按下一步進入配位流程後才停止，但不會通過選位確認。
B 區停用時可先前進 C 區；此時也不能宣稱指定年份已經驗證完成。

本機測試涵蓋日期格式、文案缺失、重複／停用選項、DOM 重排與改字、年份錯誤／缺失、
確認前年份改變，以及跳過停用票種後仍須核對完整場次。未使用修改後程式進行實站購票。


## 日期與時間停用實站證據及限制

2026-10-03 唯讀觀察 BIGBANG 活動 `102001041-bigbang-tpe-2026`：
日期 `10月9日(週五)`、時間 `18:00` 均為可見 div，class 為
`spec-LwNjSh disabled-ImixBj soldout-sBHQQa`，無 active、disabled 屬性或 aria-disabled。
頁面顯示已售罊，下一步具有 disabled 屬性。不能只靠 Playwright isEnabled 判斷 div。
此樣本證明停用＋售罄組合，不證明 disabled 單獨代表不可售。

尚未觀察可操作多場次頁面的下游更新完成訊號。因此本次採保守界線：
若本次選票已點選日期／時間，之後遇停用時間／票種就停止，
不將可能殘留的舊場次狀態當成下一順位依據。不以固定等待或日期 active 當成刷新完成。
下游可選時仍走完整選票及配位場次核對；這不是對所有跨場次更新情況的實站驗證。
即使點選前沒有 active，仍採用相同保守界線；無 active 不足以證明下游沒有舊資料。
日期或時間的已知過期提示仍走既有恢復；真正驗證失敗不重新分類成恢復。
