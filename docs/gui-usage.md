# 本機 GUI：平台首頁與 Klook 購票

## 金額改由人工確認

GUI 不再要求幣種、單價或總價。工具仍核對活動、日期、時間、完整票種名稱、張數與配位，在確認到達付款頁後停止；付款前請自行核對網站金額。票種名稱只能唯一匹配，同名不同價或同名但停用狀態不同，都不會自行挑選。名稱中的單人票、VIP、票區數字仍保留，不明後綴不猜測。若網站直接以 `NT$6,980` 作為票種名稱，可填入相同文字；只正規化全半形與空白，不把不同幣別、金額、千分位寫法或內場／看台視為相同票種。

舊活動可讀取，幣種與單價在轉換時忽略，重新保存後移除。舊執行紀錄仍保留，活動列表標示「舊版執行紀錄」。舊版未決開始請求不能安全轉換，會阻擋重送，不清除紀錄、不自動續購；先人工檢查原瀏覽器、訂單與程序，確認沒有未處理的提交後，再關閉舊分頁並使用重新啟動的 GUI 網址開新分頁。不可在購票中途更新程式。

## 啟動與四個步驟

在專案目錄執行 `npm run gui`，程式會開啟本機網頁。若沿用原本的自動化識別參數測試，使用 `WEBDRIVER_EXPERIMENT=1 npm run gui`。`npm run gui -- --no-open` 只印出網址。

啟動後先顯示平台首頁，在 Klook 列按「進入平台」開啟原本的活動列表。平台以表格列出名稱、目前狀態與操作。TicketPlus 標示「尚未支援」，不提供購票入口；目前沒有新增 TicketPlus 的表單或購票流程。

Klook 活動首頁：按「新增活動」建立設定，或在列表按「使用活動」進入四步驟。列表以不同日期＋時間計算場次；同場不同票區不重複，跨場次顯示「多個場次」。

列表的「執行狀態」依每筆活動最近一次真實執行顯示：尚無執行紀錄、等待開賣、執行中、已執行；已結束後若目前活動設定與那次執行不同，顯示「設定已更新」。第一步按「下一步」就會儲存完整活動，因此活動可以已儲存但尚無執行紀錄。相同內容重存不算更新，共用聯絡資料也不影響此標籤。「已執行」不代表購票或付款成功，亦不代表瀏覽器已解除占用。

新執行紀錄以活動 ID 關聯並保存活動設定摘要值，不改動原本的請求去重判斷。舊紀錄缺少關聯、CLI 與模擬執行不推測綁定；沒有可對應紀錄時顯示「尚無執行紀錄」。同名活動以及刪除後重新建立的活動，各自獨立。

1. **活動與順位**：填入名稱、Klook 活動網址，新增並上下調整日期、時間、票種、張數。每筆順位的「複製」會將目前輸入（含未儲存或未填完的內容）插入來源正下方，兩筆可獨立修改，並取消先前的設定確認；複製本身不會儲存或開始購票。單張票不要求連位；多張可勾選。預設排除愛心席、身障、視線不良，可修改排除詞，fallback 固定 STRICT。
2. **聯絡資料**：輸入並儲存姓名、電話與 Email。修改後必須再次儲存；不受第三步未完成的時間設定影響。
3. **確認與開始**：核對購票摘要，選擇立即開始，或指定台灣時間（UTC+08:00）的開賣時間與提前 1／2 秒刷新。開始時間只在設定區顯示，不重複列入購票摘要；時間變動會取消確認。按「開始購票」後固定這份設定，保存並驗證，再發出一次啟動請求；保存或啟動遭拒留在第三步顯示原因。一般介面只提供「開始購票」；模擬能力保留供開發測試使用，不連線 Klook。保存期間鎖定前三步；另一分頁若已修改活動，自動保存時間會拒絕覆蓋並要求重新載入。
4. **執行狀態**：成功啟動後自動進入，主畫面顯示「正在購票、等待開賣、請手動登入、已到付款頁、購票已停止」及對應說明；等待開賣時顯示時間與倒數。活動名稱、紀錄起始時間、順位與恢復額度放在執行紀錄。提交結果不明或程序中斷仍會在說明中明確提醒人工檢查，不視為一般失敗。可複製日誌；停留在紀錄底部時自動跟隨新紀錄，向上查看時不強制捲動。新活動尚未開始時顯示「尚未執行」，不帶入前次紀錄。首頁的占用入口也可查看目前執行。

開始購票會沿用既有登入、開賣、順位、恢復及核對流程。需要登入時請在另開的購票瀏覽器手動登入。到付款頁便停下，**付款由使用者自行完成**。錯誤或提交結果不明時不自動重新開始。

換演唱會時按「新增活動」，或從清單載入另一場。活動各有獨立 ID，同名不互相覆蓋。首頁可刪除指定活動，確認後只移除活動設定，不刪個資、執行紀錄或占用檔。返回首頁前若活動或個資有未保存修改，會詢問是否放棄。保存、刪除及啟動在同一服務內依序處理，避免多分頁的操作互相覆蓋。仍不提供整個活動的複製或執行中的 GUI 停止按鈕。

## 檔案與既有 CLI

GUI 使用 `src/local/react/` 的 React 元件，以 Vite 打包至已忽略的 `dist/react/`。`npm run gui` 和 `npm test` 會先打包，正式首頁由同一個本機 Node 服務提供，不需要額外啟動前端服務。`npm run typecheck` 同時檢查 Node 與 React；`npm run test:gui` 執行本機 GUI 回歸測試。修改前端後，若直接使用 `node --import tsx --test ...` 執行個別測試，請先執行 `npm run build:gui`；開發中的 GUI 也需要重新打包並重新整理頁面。請修改來源檔，不要直接編輯生成檔。

React 負責表單與畫面；GUI 活動設定新增平台欄位，聯絡資料與購票引擎仍沿用既有格式。`ActivityEditor`、`ContactForm` 與 `PurchaseSummary` 管理不同區塊；`startPurchase` 保留未知請求的識別碼與設定核對；`useRunStatus` 接收狀態串流並清理訂閱，重連不觸發購票。本次仍僅支援 Klook，沒有增加 TicketPlus 平台或變更付款邊界。

- `local-data/events/<UUID>.json`：每場活動、順位與開賣時間，新版為 schemaVersion 3，settings 必須包含 platform: "klook"；原 targets 逐筆日期、時間、票種、張數與順序不變。
- `contact.local.json`：所有活動共用的聯絡資訊，格式沿用 `contact.example.json`。
- `local-data/runs/<requestId>.json`：本次執行狀態與最多 300 筆事件，用於重連及避免重複執行；不保存聯絡資料原文。
- `local-data/purchase.lock`：GUI 和 CLI 共用的瀏覽器占用紀錄。

這些本地資料均不進 Git。聯絡資料只保存在本機檔案，頁面載入後可編輯；不要分享 contact.local.json 或 browser-profile。活動在執行前轉成既有 PurchaseConfig；worker 使用啟動時的設定快照，修改表單不會改變正在執行的流程。

`npm start` 仍使用 `src/config/event.config.ts` 和 contact.local.json，不會自行改用 GUI 選中的活動。GUI 與 CLI 共用占用檢查，不能同時使用同一購票瀏覽器。

## 平台導航與舊活動升版

「返回活動首頁」回到 Klook 列表；點擊左上角「TicketPilot」離開 Klook 工作區並返回平台首頁。未儲存活動或聯絡資料時，離開前會確認是否放棄；取消則保留草稿。保存、開始請求或關閉購票瀏覽器尚未完成時不能切換。導航不停止購票、不解除占用、不清除未知請求。平台首頁不載入 Klook 聯絡資料，因此聯絡檔損壞不妨礙返回首頁及查看執行狀態，但 Klook 的啟動驗證不會放寬。

版本 1 活動會先按舊格式嚴格驗證，再在記憶體補上 `platform: "klook"`。載入本身不寫檔、不改 ID 或更新時間。首次保存時，先在同一目錄建立 `<UUID>.json.v1.bak`，保存原檔的完整內容，再把活動寫成版本 3。備份以獨占方式建立；若已有不同內容、寫入失敗或不完整備份，會停止保存並要求人工確認，不覆寫原活動。後續保存不覆蓋既有備份。舊價格欄位仍依原有規則忽略，保存後移除。

先前實驗格式使用過版本 2（場次＋共用順位），本版不將它推導成原始 targets，也不自動刪除。版本 3 或 API 請求缺平台、平台尚未支援、網址不屬於 Klook 時，一律拒絕；不能靠缺少平台繞過檢查。活動檔案 API 回傳的 `schemaVersion` 表示來源檔案版本，`settings` 則一律已驗證並含平台。

回退 Git 只還原程式，不會還原 `local-data`。若需要讓舊程式使用已升版活動，先停止 GUI、確認沒有購票程序或未處理提交，另存目前活動檔後，再將對應 `.v1.bak` 複製回原 `.json`。新版建立的活動沒有舊版備份，不提供自動降版。不要使用活動備份覆蓋聯絡資料、執行紀錄或占用檔。

購票請求版本與活動檔案版本分開管理。新請求使用版本 4；舊版（無版本、2、3）執行紀錄仍可讀，但不允許用同一舊請求重新開始，舊前端待確認請求也保持原樣。平台是新設定指紋的一部分，不能在請求中途切換。GUI、CLI 與模擬仍共用既有占用規則。

## React 目錄

- `App.tsx`：平台導覽與全域執行狀態，`useRunStatus` 只有一份。
- `pages/PlatformHome.tsx`：平台表格與目前狀態入口。
- `platforms/klook/`：Klook 活動列表、四步工作區、表單、摘要及開始請求。保留原本的欄位與布局。
- `shared/api.ts`：本機 API、token 與錯誤處理。
- `shared/runs/`：狀態訂閱、日誌呈現與關閉瀏覽器控制。

目前採 React 內部狀態導航，沒有新增網址路由；重新整理回平台首頁。未實作的平台不建立空白工作區或通用表單框架。未來加入其他平台時，表單與必要資料由平台自行定義，不能只隱藏 Klook 聯絡資料頁就繞過後端驗證。

## 關閉、重連與異常

流程成功到達付款頁或失敗停止後，第四步會在本服務仍可控制瀏覽器時提供「關閉購票瀏覽器」。先完成必要的人工檢查／付款，再按此按鈕並確認，或手動關閉購票瀏覽器；等程序也結束後才會解除占用。按鈕只關閉本次購票瀏覽器，不關閉 GUI、不取消訂單，也不改寫執行結果。執行中、其他程序占用或服務重啟後失去控制時不提供此按鈕；關閉失敗不會強制解除占用。只到付款頁不代表可以開始下一輪。GUI 服務在購票子程序仍執行時會拒絕 Ctrl+C 關閉，提示先關閉購票瀏覽器。

重新整理 GUI 先回平台首頁。平台首頁的 Klook 列可進入平台；有執行中流程、瀏覽器占用、提交結果不明或程序異常中斷時，提供「查看狀態」，在同一頁面切換到既有執行狀態頁。查看與返回不會啟動購票。一般失敗或到達付款頁後，解除占用且瀏覽器已關閉就恢復「可使用」。首頁不提供最近購票／模擬結果入口，也不刪除紀錄。Klook 活動列表仍不顯示已結束且解除占用的狀態入口；紀錄仍保留於本機，第四步仍可顯示本次執行結果。仍占用則顯示「查看目前狀態」，模擬執行中提供「查看模擬狀態」；解除占用或模擬結束後，Klook 活動列表的占用提示與入口會隱藏，平台首頁也移除入口；提交結果不明或異常中斷則持續顯示「需要人工確認」，不提供人工清除狀態的功能。首頁或表單中接收 SSE 不會強制跳頁，也不重跑。購票／瀏覽器占用或模擬進行中，首頁暫停新增、使用及刪除，可查看狀態；後端同時阻擋刪除與第二次啟動。開始請求回應未知時，保留原 requestId 與內容簽章；再次開始若改過內容會在自動保存時間之前停止，不會用新時間另開一輪。聯絡資料原文不寫入此瀏覽器儲存。相同 requestId 不會建立第二個購票程序；不同設定不能重用同一請求。服務重啟會載入先前紀錄，平台首頁只呈現進行中或待處理狀態，Klook 活動列表不顯示已結束且解除占用的狀態入口；不會自動續購。

若強制終止程序或電腦重開，占用檔可能保留。**不要直接再啟動購票**：先確認 Klook 訂單、關閉原購票 Chrome，確認舊 GUI／CLI／worker 均已停止。確認沒有未處理訂單或仍在提交的程序後，才可人工移除專案下 `local-data/purchase.lock`，重新啟動 GUI。程式不以 PID 或等待時間推測可以安全解鎖。不要刪除 runs 紀錄來重送同一請求。

本機 API 僅監聽 127.0.0.1，驗證 Host、Origin 與頁面 token。未加入遠端部署與多人帳號支援。

## 驗證範圍

本批以本機表單、JSON 儲存、fixture worker、攔截頁面與既有測試驗證，不經 GUI 執行真實購票。模擬完成不代表已取得票券；仍需由使用者進行實站驗收。

修改程式後請關閉舊 GUI 服務，再執行 `npm run gui` 並使用新網址，確保畫面與後端版本一致。


## 組合套票與取票方式

在「活動與順位」的獨立「套票設定」區塊勾選「啟用組合套票」後，每個順位都要填入套票名稱，例如 `演唱會套票 1`。複製順位會保留套票內容，清空順位也會清掉套票。GUI 的取票方式由活動共用，只有勾選套票時可輸入，例如 `指定地點自取`；網站沒有此群組時可留空。主動關閉開關會清除取票方式與所有套票值，重新啟用需重新填寫。舊活動不會自動啟用新欄位。若舊活動僅有取票方式，GUI 保留原值並提示：啟用套票且補齊順位，或按「清除舊取票設定」後才能儲存及開始；載入本身不改檔案。CLI 與底層設定仍相容獨立取票方式。

選票頁的群組標題忽略尾端括號備註。新選項以完整名稱或有明確分隔的開頭匹配；`演唱會套票 1` 可匹配 `演唱會套票1：門票＋eSIM`，不會匹配套票 10 或 1A。`郵寄` 同時匹配本島與海外時會停止，請填完整名稱。票種本身仍使用原有完整匹配。

設定有值卻找不到選項、頁面出現群組但沒有設定、名稱有歧義、選項停用或操作後被重設，均停止，不按下一步。新群組停用不會自動換順位，因此套票 1 停用不代表會改選套票 2。其他已支援的順位切換與過期恢復規則保持不變，恢復後重新選取。選位、個資及付款頁未增加這兩項審核。

CLI 可在活動設定填入 `bundleEnabled: true`、`deliveryMethod: "指定地點自取"`，並在每筆 target 加入 `bundle: "演唱會套票 1"`。啟用卻缺名稱會在開啟瀏覽器前拒絕。未啟用時省略新欄位，以保持舊設定與執行紀錄的比較相容。

驗證採本機 fixture；已觀察的實站 DOM 只有停用狀態，可售時的選中標記、載入完成及連動行為仍待實站驗證，不代表套票活動已完整相容到付款頁。
