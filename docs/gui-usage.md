# 本機 GUI：TicketPlus 購票與登記抽選

## 啟動與活動列表

在專案目錄執行 `npm run gui`，程式會開啟本機網頁。若使用自動化識別參數測試，執行 `WEBDRIVER_EXPERIMENT=1 npm run gui`。`npm run gui -- --no-open` 只印出網址。

啟動與重新整理後直接進入 TicketPlus 活動列表。按「＋」新增活動，或按「編輯活動」載入設定。列表載入失敗時可以重新載入。

列表顯示每筆活動最近一次執行的狀態。活動儲存不代表已開始購票；「已執行」也不代表購票成功、已付款或瀏覽器已解除占用。執行後修改活動設定，列表會標示「設定已更新」。同名活動各有獨立 ID，刪除後重建也不會接續原活動的紀錄。缺少活動關聯的舊紀錄不會依名稱猜測綁定。

## 三個步驟

1. **活動與順位**：填入 TicketPlus 活動網址與名稱，選擇「購票」或「登記抽選」，並設定日期、時間、完整票種名稱及張數。順位必須為同日期、同時間。可以新增、複製、刪除及調整順序；複製會保留當下草稿，但不會自動儲存或購票。按「下一步」儲存成功後才進入確認頁。
2. **確認與開始**：核對已儲存摘要，選擇立即開始或指定台灣開賣時間，並設定最長執行時間。修改時間或其他設定會取消先前確認。未儲存的活動修改不會進入摘要，也不能開始。開始時會保存並驗證設定，再送出啟動請求；其他分頁已修改活動時，會拒絕覆蓋並要求重新載入。
3. **執行狀態**：顯示登入、開賣等待、選票與後續處理進度。需要登入時，請在另開的購票 Chrome 手動登入；確認成功後自動繼續。可查看與複製日誌；向上閱讀時不會被強制捲回底部。

最長執行時間必須為 10～1440 的整數分鐘。新活動與舊缺值活動預填 10；舊 1～9 分鐘設定可載入，但須修改後才能啟動。期限從開始選場次前計算，不包含登入、開賣等待與抽選參加者填寫等待。

指定開賣時間可提前 1／2 秒刷新。只有目標場次明確顯示尚未開賣，才會在至少 3 秒後再次刷新；開賣準備最多等到開賣後 2 分鐘。完整規則見 [開賣時間設定](sale-schedule.md)。

## 購票流程

工具以設定的活動、日期、時間、完整票種名稱及張數核對結果，不以按鈕可點擊代表資料正確。只有明確售完才跳過票種。送出後辨識售完提示，必須確認彈窗關閉、選票頁與張數重新核對通過，才嘗試本輪下一順位。全部順位耗盡後更新票數，確認更新完成才開始新輪。

未知畫面、殘留張數、資料不符、一般失敗、更新結果無法確認或提交結果不明都會停止，不盲目重送。坐席活動先核對確認選位結果的票區與張數；不符時停止，網站可能仍保留座位，請自行檢查。

抵達同場次資料頁後，程式核對必要資料、勾選服務條款並按一次下一步，確認到達付款頁後停止，不按「前往付款」。會員聯絡欄位由網站帶入，工具不比對聯絡資料，也不需要本機聯絡資料設定。**付款方式、幣種、金額與付款都由你自行確認。**

點擊下一步前停止時，結果會說明尚未送出。按下後無法確認結果時，不會重按或重新開始，請人工檢查網站。

## 登記抽選

選擇「登記抽選」時，程式按「立即登記」，選擇票區與張數，送出後抵達輸入資料頁並等待。請在購票瀏覽器為每位參加者按「編輯」，自行填寫國籍、證件姓名與證件號碼；程式不讀取、不保存、不代填這些資料。

填完後回 GUI 按「參加者已填完」，每次等待只送出一次確認。程式核對參加者列數等於張數、每列已填，且沒有開著的編輯視窗，再勾選條款並按一次下一步，停在「確認登記」之前。請自行檢查並完成最後登記。

等待填寫期間不消耗最長執行時間，但網站倒數仍有效。倒數結束、離開輸入資料頁或要求停止時，流程停止。參加者確認傳送結果不明時，不會重送；請查看執行狀態與網站，必要時要求停止。工具不會送出最終登記。

## 導覽、停止與關閉

首頁與返回操作都會回到 TicketPlus 活動列表。活動有未儲存修改時，離開前會確認是否放棄；取消則保留草稿。保存、啟動或關閉瀏覽器尚未完成時，相關操作會鎖定。導覽不停止購票、不解除占用，也不清除待確認的請求。

執行中可按「停止購票」。送出停止要求不代表已停止，須等待結果確認；也不代表網站端的請求已取消。購票瀏覽器會保留供你檢查。抽選填寫等待同樣可以停止。

流程結束且本服務仍可控制瀏覽器時，提供「關閉購票瀏覽器」。請先完成必要的人工檢查、付款或登記，再按按鈕並確認，或手動關閉購票 Chrome。按鈕不取消訂單、不關閉 GUI，也不改寫執行結果。等流程與瀏覽器都結束後才釋放占用。

執行中、其他程序占用或服務重啟後失去控制時，不提供關閉按鈕；關閉失敗不會強制解鎖。GUI 服務在購票子程序仍執行時會拒絕 Ctrl+C 關閉，提示先關閉購票瀏覽器。

## 重連、待確認請求與異常

重新整理 GUI 或重新連上狀態串流，不會重新購票。活動列表保留目前執行與待人工確認狀態的入口；無法對應活動的紀錄可在獨立結果頁查看。只有占用鎖、沒有可用紀錄時，顯示未知程序占用，不猜測所屬平台。

開始請求的回應遺失時，GUI 保留原 requestId 與設定簽章，不能改用新 ID 自動重試。可查看待確認的啟動結果；只有匹配原請求的結果，或後端明確拒絕，才清除待確認狀態。相同請求不會啟動第二個 worker；不同設定不能重用同一請求。

活動刪除只移除設定，不刪除執行紀錄、私人資料或占用鎖。購票或瀏覽器仍被占用時，不能開始另一輪或刪除活動。

若強制終止程序或電腦重開，占用檔可能保留。先檢查網站訂單、關閉原購票 Chrome，確認舊 GUI／worker 已停止，且沒有未處理訂單或仍在提交的請求，再人工處理 `local-data/purchase.lock`。程式不以 PID 或等待時間猜測可以安全解鎖。不要刪除 runs 紀錄來重送同一請求。

## 本機資料與舊 Klook 版本

- `local-data/events/<UUID>.json`：活動設定，版本為 `schemaVersion: 3`，`settings.platform` 必須為 `ticketplus`。購票順位保存在 `targets` 陣列；舊單一 `target` 活動格式不會自動轉換。
- `local-data/runs/<requestId>.json`：執行狀態及最多 300 筆事件，用於重連與避免重複執行。TicketPlus 現有歷史指紋相容規則保留。
- `local-data/purchase.lock`：持久購票占用紀錄。
- `browser-profile-ticketplus/`：TicketPlus Chrome 登入資料。

這些資料均不進 Git。worker 使用啟動時的設定快照，修改表單不會改變已開始的流程。`ticketplus.example.json` 只提供格式範例，GUI 不會自動匯入；GUI 是唯一執行入口。

完整 Klook 程式與當時文件保存在 `archive/klook`。本版只辨識必要的舊資料結構：有效舊 Klook 活動與執行紀錄不顯示、不改寫、不刪除，也不自動升版或建立備份。GUI 與 API 不再提供 Klook 活動的新增、載入、修改、刪除或購票。重用舊 Klook 請求 ID 會在取得占用鎖或啟動 worker 前被拒絕。

缺少必要欄位、未知版本或平台矛盾的活動檔仍計入無法載入數量；損壞執行紀錄會阻止服務啟動，須人工檢查。隱藏舊 Klook 紀錄不會解除既有占用鎖。私人 `contact.local.json` 與舊 `browser-profile/` 仍保留，也繼續由 Git 忽略。

需要管理 Klook 資料時，先停止 GUI 並確認沒有購票程序或未處理提交，再使用 `archive/klook`。切換 Git 分支只切換程式，不會還原或清理本機資料。

## 開發與驗證

GUI 來源位於 `src/local/react/`，由 Vite 打包至已忽略的 `dist/react/`，由本機 Node 服務提供。`npm run gui` 和 `npm test` 會先建置；`npm run typecheck` 檢查 Node 與 React，`npm run test:gui` 執行 GUI 回歸測試。直接執行個別 GUI 測試前，先執行 `npm run build:gui`。

`App.tsx` 管理唯一的全域狀態訂閱、TicketPlus 工作區與獨立結果頁；`platforms/ticketplus/` 管理活動草稿、三步驟流程與啟動請求；`pages/` 提供列表、活動編輯與確認頁；`shared/runs/` 管理狀態訂閱、日誌與關閉控制。摘要只轉換已儲存設定，不作為購票請求來源。

本機 API 僅監聽 `127.0.0.1`，驗證 Host、Origin 與頁面 token，不支援遠端部署或多人帳號。

本機 fixture、攔截路由與 headless Playwright 測試不代表實站購票成功。修改程式後請關閉舊 GUI，重新啟動並使用新網址，確保前後端版本一致；不要在購票中途更新程式。
