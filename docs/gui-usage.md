# GUI 第二批：完整表單與實際執行（階段 4–6）

## 啟動與四個步驟

在專案目錄執行 `npm run gui`，程式會開啟本機網頁。若沿用原本的自動化識別參數測試，使用 `WEBDRIVER_EXPERIMENT=1 npm run gui`。`npm run gui -- --no-open` 只印出網址。

啟動後先顯示活動首頁：按「新增活動」建立設定，或在列表按「使用活動」進入四步驟。列表以不同日期＋時間計算場次；同場不同票區不重複，跨場次顯示「多個場次」。

列表的「執行狀態」依每筆活動最近一次真實執行顯示：尚無執行紀錄、等待開賣、執行中、已執行；已結束後若目前活動設定與那次執行不同，顯示「設定已更新」。第一步按「下一步」就會儲存完整活動，因此活動可以已儲存但尚無執行紀錄。相同內容重存不算更新，共用聯絡資料也不影響此標籤。「已執行」不代表購票或付款成功，亦不代表瀏覽器已解除占用。

新執行紀錄以活動 ID 關聯並保存活動設定摘要值，不改動原本的請求去重判斷。舊紀錄缺少關聯、CLI 與模擬執行不推測綁定；沒有可對應紀錄時顯示「尚無執行紀錄」。同名活動以及刪除後重新建立的活動，各自獨立。

1. **活動與順位**：填入名稱、Klook 活動網址，新增並上下調整日期、時間、票種、單價、張數。單張票不要求連位；多張可勾選。預設排除愛心席、身障、視線不良，可修改排除詞，fallback 固定 STRICT。
2. **聯絡資料**：輸入並儲存姓名、電話與 Email。修改後必須再次儲存；不受第三步未完成的時間設定影響。
3. **確認與開始**：核對購票摘要，選擇立即開始，或指定台灣時間（UTC+08:00）的開賣時間與提前 1／2 秒刷新。開始時間只在設定區顯示，不重複列入購票摘要；時間變動會取消確認。按「開始購票」後固定這份設定，保存並驗證，再發出一次啟動請求；保存或啟動遭拒留在第三步顯示原因。一般介面只提供「開始購票」；模擬能力保留供開發測試使用，不連線 Klook。保存期間鎖定前三步；另一分頁若已修改活動，自動保存時間會拒絕覆蓋並要求重新載入。
4. **執行狀態**：成功啟動後自動進入，主畫面顯示「正在購票、等待開賣、請手動登入、已到付款頁、購票已停止」及對應說明；等待開賣時顯示時間與倒數。活動名稱、紀錄起始時間、順位與恢復額度放在執行紀錄。提交結果不明或程序中斷仍會在說明中明確提醒人工檢查，不視為一般失敗。可複製日誌；停留在紀錄底部時自動跟隨新紀錄，向上查看時不強制捲動。新活動尚未開始時顯示「尚未執行」，不帶入前次紀錄。首頁的占用入口也可查看目前執行。

開始購票會沿用既有登入、開賣、順位、恢復及核對流程。需要登入時請在另開的購票瀏覽器手動登入。到付款頁便停下，**付款由使用者自行完成**。錯誤或提交結果不明時不自動重新開始。

換演唱會時按「新增活動」，或從清單載入另一場。活動各有獨立 ID，同名不互相覆蓋。首頁可刪除指定活動，確認後只移除活動設定，不刪個資、執行紀錄或占用檔。返回首頁前若活動或個資有未保存修改，會詢問是否放棄。保存、刪除及啟動在同一服務內依序處理，避免多分頁的操作互相覆蓋。仍不提供複製或執行中的 GUI 停止按鈕。

## 檔案與既有 CLI

- `local-data/events/<UUID>.json`：每場活動、順位與開賣時間，格式沿用第一批 schemaVersion 1。
- `contact.local.json`：所有活動共用的聯絡資訊，格式沿用 `contact.example.json`。
- `local-data/runs/<requestId>.json`：本次執行狀態與最多 300 筆事件，用於重連及避免重複執行；不保存聯絡資料原文。
- `local-data/purchase.lock`：GUI 和 CLI 共用的瀏覽器占用紀錄。

這些本地資料均不進 Git。聯絡資料只保存在本機檔案，頁面載入後可編輯；不要分享 contact.local.json 或 browser-profile。活動在執行前轉成既有 PurchaseConfig；worker 使用啟動時的設定快照，修改表單不會改變正在執行的流程。

`npm start` 仍使用 `src/config/event.config.ts` 和 contact.local.json，不會自行改用 GUI 選中的活動。GUI 與 CLI 共用占用檢查，不能同時使用同一購票瀏覽器。

## 關閉、重連與異常

流程成功到達付款頁或失敗停止後，第四步會在本服務仍可控制瀏覽器時提供「關閉購票瀏覽器」。先完成必要的人工檢查／付款，再按此按鈕並確認，或手動關閉購票瀏覽器；等程序也結束後才會解除占用。按鈕只關閉本次購票瀏覽器，不關閉 GUI、不取消訂單，也不改寫執行結果。執行中、其他程序占用或服務重啟後失去控制時不提供此按鈕；關閉失敗不會強制解除占用。只到付款頁不代表可以開始下一輪。GUI 服務在購票子程序仍執行時會拒絕 Ctrl+C 關閉，提示先關閉購票瀏覽器。

重新整理 GUI 先回活動首頁。首頁不顯示已結束且解除占用的購票或模擬紀錄；紀錄仍保留於本機，第四步仍可顯示本次執行結果。仍占用則顯示「查看目前狀態」，模擬執行中提供「查看模擬狀態」；解除占用或模擬結束後首頁提示與入口會隱藏。首頁或表單中接收 SSE 不會強制跳頁，也不重跑。購票／瀏覽器占用或模擬進行中，首頁暫停新增、使用及刪除，可查看狀態；後端同時阻擋刪除與第二次啟動。開始請求回應未知時，保留原 requestId 與內容簽章；再次開始若改過內容會在自動保存時間之前停止，不會用新時間另開一輪。聯絡資料原文不寫入此瀏覽器儲存。相同 requestId 不會建立第二個購票程序；不同設定不能重用同一請求。服務重啟會載入先前紀錄，但首頁不顯示已結束且解除占用的紀錄，也不自動續購。

若強制終止程序或電腦重開，占用檔可能保留。**不要直接再啟動購票**：先確認 Klook 訂單、關閉原購票 Chrome，確認舊 GUI／CLI／worker 均已停止。確認沒有未處理訂單或仍在提交的程序後，才可人工移除專案下 `local-data/purchase.lock`，重新啟動 GUI。程式不以 PID 或等待時間推測可以安全解鎖。不要刪除 runs 紀錄來重送同一請求。

本機 API 僅監聽 127.0.0.1，驗證 Host、Origin 與頁面 token。未加入遠端部署與多人帳號支援。

## 驗證範圍

本批以本機表單、JSON 儲存、fixture worker、攔截頁面與既有測試驗證，不經 GUI 執行真實購票。模擬完成不代表已取得票券；仍需由使用者進行實站驗收。

修改程式後請關閉舊 GUI 服務，再執行 `npm run gui` 並使用新網址，確保畫面與後端版本一致。
