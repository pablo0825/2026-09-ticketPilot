# 活動場次欄位擷取

## 2026-10-16 側邊瀏覽器唯讀觀測

觀察同一活動頁的初次導覽、重新載入、390 × 844 窄版與還原寬版。未點擊立即購買、加票或提交。沒有設定網路節流；連續取樣只證明觀察到的載入階段，不代表精確的載入時間。

場次位於 `.sesstion-item`；名稱使用 `.font-weight-bold.is-word-break`。日期與時間分別使用以下結構（省略版面 class 與框架屬性）：

```html
<div class="d-flex mb-2 mb-md-0">
  <div class="wordBreakKeepAll d-block d-md-none">日期</div>
  <div>2026-10-30(五)</div>
</div>
<div class="d-flex mb-2 mb-md-0">
  <div class="wordBreakKeepAll d-block d-md-none">時間</div>
  <div>20:00</div>
</div>
```

寬版標籤為 `display:none`，窄版為 `display:block`；值與容器保持可見。因此標籤只作結構定位，讀取值仍須通過可見性檢查。

載入時名稱為 `Loading...`。寬版日期值容器有兩個子 div，中間為 `~` 文字；窄版為同一文字節點的日期範圍。時間值為 `19:00 ~ 23:59`。兩種版面皆在相同標籤的相鄰值容器內。

連續取樣也觀察到：正式名稱、日期、時間已出現，購買按鈕所在區塊卻暫時顯示 `role="progressbar"`，內含 SVG circle，稍後才顯示按鈕。這個圖形在場次列內、日期時間欄位外。舊的整列末端元素掃描會涵蓋它；此結構支持本機重現，但不能追溯證明每筆歷史 `other-read-error` 都來自它。

## 擷取與驗證邊界

活動日期與時間改以 `div.wordBreakKeepAll` 的固定標籤、可見 `.d-flex` 父容器及可見相鄰 div 值定位。只從值容器讀取 `innerText`，不掃描同列按鈕、地點或圖示。日期欄位只接受完整單日或兩日 `~` 區間，不從其他文案抽出日期片段；時間區間保持獨立，不變成單一時間。

快照保留 `dateField` / `timeField` 的 labels / values 數量，parser要求每種欄位與值容器各一個；重複但空的欄位也不得通過，這是縮小來源後保留唯一性所需的結構核對。原始日期、時間、活動及按鈕核對仍保留，未取第一筆或去重。活動欄位診斷也帶出固定結構數量，方便識別拒絕原因。

登入、readiness、等待期限、點擊、更新票數、順位與提交程式不改。共用活動parser的開賣準備、點擊後活動殘留也使用此欄位核對；票種售完的leafTexts未修改，不能宣稱所有DOM擷取例外均已消除。

測試以實際欄位關係重建本機fixture；驗證寬窄、圖示加入/移除、欄位外干擾、缺失/重複/空欄位、隱藏副本與範圍。外部回應gate控制圖示到完整按鈕的變化，讀取器不決定fixture完成時機；等待期間零點擊，完整後只點一次本機購買按鈕。未操作實站購票。
